# learning-memo

Rust学習中の対話を自動的に学習メモへ記録するskill。

## いつ起動するか（重要）

**ユーザーが「メモして」と言わなくても、以下の状況では自発的に起動する。**

| 状況 | 例 | 記録先カテゴリ |
|---|---|---|
| 新しい概念を質問された | 「ライフタイムって何？」 | 質問・疑問 |
| ユーザーが理解した | 「なるほど、所有権が分かった」 | 学んだこと + 理解度メモ |
| ユーザーが躓いた | 「ここ難しい」「混乱する」 | 理解度メモ（躓きポイントとして） |
| 概念を解説した直後 | （Claudeが何かを説明した後） | 学んだこと（要約として） |
| 誤解が判明した | 「あ、違うんですね」 | 理解度メモ |
| 明示依頼 | 「これメモして」 | 指示された内容に応じて |

## 動作手順

### 1. 現在のフェーズを特定
- `roadmap/README.md` の「## 現在のフェーズ」を読む
- フェーズ番号 `{NN}` と名前 `{name}` を取得

### 2. 該当の notes ファイルを Read
- `roadmap/{NN}-{name}-notes.md` を Read
- **既存内容を絶対に壊さない**ため、必ず Read してから Edit する

### 3. 当日の日付セクションを探す
- `## YYYY-MM-DD` 形式（例: `## 2026-05-05`）
- 今日の日付セクションが既にあれば、そこに追記
- なければ、ファイル末尾に新しい日付セクションを作成

### 4. 適切なカテゴリに追記

各日付セクション内には3カテゴリがある：

```markdown
## YYYY-MM-DD

### 学んだこと
- 新しく理解した概念や知識を箇条書き

### 質問・疑問
- ユーザーが投げた質問、まだ解消していない疑問

### 理解度メモ
- 理解の深さ、躓いたポイント、誤解していた点
```

該当のカテゴリの末尾に1〜数行で追記する。

### 5. 追記内容の書き方

- **簡潔に**: 1項目1〜2行
- **何が起きたか具体的に**: 「Vec<T>について理解した」ではなく「Vec<T>がPythonのlistと違って要素型が固定だと理解した」
- **時系列の自然な記録**: 大量の情報を1度に書かず、対話の流れに沿って小刻みに追記
- **ユーザーの言葉を尊重**: ユーザーが使った表現を活かす

## 重要なルール

1. **追記のみ。既存内容を壊さない**: Edit時は必ず Read 後の内容を確認し、追記箇所を慎重に選ぶ。
2. **静かに記録する**: メモを書いたことを毎回大々的に報告しない。「メモに記録しておきました」程度の一言でOK、または何も言わずに次の対話に進む。
3. **重要度を判断する**: 全ての発言を記録するのではなく、「学習履歴として残す価値があるか」を判断する。雑談や些末な確認は記録しない。
4. **質問は解消したら更新する**: ユーザーの質問が解消されたら、「質問・疑問」から「学んだこと」へ移すか、解消の追記をする。
5. **CLAUDE.md の語彙ルールに従う**: メモ内でも専門用語に必要な括弧補足を入れる。

## 例

ユーザー: 「`&str` と `String` の違いって何？」
Claudeが解説した後、メモに以下を追記：

```markdown
## 2026-05-05

### 学んだこと
- `&str` と `String` の違い: `&str` は文字列スライス（借用、固定長）、`String` はヒープ確保された可変文字列

### 質問・疑問
- (前: `&str` と `String` の違いって何？ → 解消)
```
