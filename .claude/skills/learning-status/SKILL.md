# learning-status

Rust学習プロジェクトの「現在地」を把握するためのskill。

## 動作手順

### 1. 現在のフェーズを特定
- `roadmap/README.md` を読む
- 「## 現在のフェーズ」セクションから現在のフェーズ番号と名前を取得
  - 例: 「フェーズ1: 基礎構文」

### 2. 現在のフェーズの3ファイルだけを読む

`{NN}` は現在のフェーズ番号（01〜04）、`{name}` はフェーズ名（basics / cli / async / web-api）。

- `roadmap/{NN}-{name}.md`（学習トピック）
- `roadmap/{NN}-{name}-todo.md`（チェックリスト）
- `roadmap/{NN}-{name}-notes.md`（学習メモ）

**他フェーズは読まない**（コンテキスト節約のため）。

### 3. 実装状況を確認（プロジェクトがあるフェーズのみ）

該当フェーズに実装プロジェクトがある場合、ソースコードを軽く確認する。

すべてのプロジェクトは **`practice/` 配下** に置かれる方針:
- **フェーズ2**: `practice/task-cli/`
- **フェーズ4**: `practice/task-api/`
- **フェーズ1, 3**: `practice/` 配下の練習用サブディレクトリ（`practice/hello-world/`, `practice/async-practice/` など）

確認手順:
1. Glob でプロジェクトディレクトリの構造を把握（`practice/**/Cargo.toml`, `practice/**/*.rs` など）
2. `Cargo.toml` を読んで依存クレートとプロジェクト状態を把握
3. `src/main.rs` / `src/lib.rs` / `src/**/*.rs` を**軽く**読み、どこまで実装が進んでいるかを把握
   - 全ファイル精読は不要。**「どの機能まで実装されているか」が分かる程度**でOK
   - ハンドラやコマンド関数の有無、未実装の `todo!()` マクロや空関数の有無をチェック
4. ディレクトリが存在しない / 空 / `cargo new` 直後の状態 → 「未着手」として扱う

注意:
- ソースコードの読みすぎはコンテキスト圧迫の原因になる。**全体像を掴む** のが目的
- 詳細な実装レビューは別タスク（このskillの責務外）

### 4. サマリを提示

以下の構造でユーザーに報告：

```markdown
## 現在の学習状況

**フェーズ**: フェーズN: XXX

### これまでの学習履歴
（notes ファイルの内容を要約。最近の3〜5件をピックアップ）

### TODO進捗
- 完了: X / 全Y件（Z%）
- 直近で完了した項目: ...
- 未完了の項目（次にやる候補）: ...

### 実装状況（該当フェーズのみ）
- プロジェクトディレクトリ: あり / なし
- 実装済み機能: ...（main.rs / lib.rs などから読み取った範囲）
- 未実装機能: ...

### 次のアクション提案
（TODO・実装状況・notes の質問を総合して、論理的な次のステップを2〜3個提案）
```

### 5. ユーザーへの確認

サマリ提示後、「この方向で進めますか？」「他にやりたいことがありますか？」と短く問いかける。

## 注意事項

- **全フェーズのファイルを読まない**。コンテキスト圧迫を避けるため、現フェーズの3ファイル + README のみ。
- 進捗は **TODOファイルのチェックボックス（`[x]` / `[ ]`）** から判定する。
- ユーザーがチェックを更新していない場合は notes やこれまでの会話から推測してよいが、その旨を明示する。
- README.md の「現在のフェーズ」が実態と合っていないと感じた場合は、ユーザーに確認を促す。
